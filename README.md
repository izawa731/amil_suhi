# 数秘自動計算

ローマ字の名前と生年月日を入れて「鑑定する」を押すと、数秘の結果を表示する1ファイルのWebページです。
`index.html` をブラウザで開くだけで動きます（サーバー不要）。

## 画面の構成
- 左：Birthday（年・月・日）／Name（ローマ字）／鑑定する
- 右（上から）
  1. あなたの基本となる３つの魂の数字は…（過去数・現在数・未来数。それぞれ意味の説明とキーワードつき）
  2. Name / Birthday
  3. 5つの数：性格・考え方（LP）／心の願い・好き嫌い（S）／行動・役割（D）／第一印象・見た目（P）／将来のテーマ（M）
  4. 鑑定結果を画像で保存（1080×1350 の PNG）

背景は「昼の森」をキャンバスで描いています（写真は使っていません）。
字体はページ・画像とも丸ゴシックの **Zen Maru Gothic**（Google Fonts）です。鑑定結果は上から順にフェードインで表示します（動きを減らす設定の端末ではすぐ表示）。

## 名前の入力
- 名前は**ひらがな**（カタカナも可）で入力します。入力すると、パスポートと同じヘボン式ローマ字が下の欄に自動で入ります（`toHepburn()`）。
  - のばす音は書かない（さとう→SATO、おおの→ONO。ただし いのうえ→INOUE）／小さい「っ」は重ねる（はっとり→HATTORI、はっちょう→HATCHO）／「ん」は B・M・P の前で M（なんば→NAMBA）
  - パスポートと違う場合は、ローマ字の欄を手で直せます。計算にはローマ字の欄を使います。
  - 漢字は読み方がわからないため、案内を出して止めます。
- 「ヘボン式ローマ字」を押すと書き方のガイドが開きます。
- スマホでは入力欄の文字を 16px にして、iPhone で画面が拡大されたままにならないようにしています。

## 計算方法
| 数 | 計算 |
|---|---|
| 性格・考え方（LP）＝現在数 | 生年月日の全桁を足す |
| 過去数 | 生まれた日 |
| 未来数 | 生まれた月日の全桁を足す |
| 行動・役割（D） | 名前の全文字（A=1…I=9, J=1…R=9, S=1…Z=8）を足す |
| 心の願い・好き嫌い（S） | 名前の母音（A・E・I・O・U）を足す |
| 第一印象・見た目（P） | 名前の子音（Y は子音）を足す |
| 将来のテーマ（M） | LP＋D |

どれも1桁になるまで各桁を足し、途中で 11・22・33 になったらそこで止めます。

### マスターナンバー（ゾロ目）の表記
LP・S・D・P・M は、足していく途中で 44・55・66・77・88・99 を通ったとき、
1桁にした数のあとに「5(77)」「8(44)」のように添えて表示します（参考サイトと同じ）。
キーワードは1桁にした数（例：5）のものを使います。過去数・現在数・未来数のカードは数字だけです。

## 文章の編集
各数のキーワードは `index.html` 内の `TEXTS`（P・LP・D・M・S・past（過去数）・present（現在数）・future（未来数） × 1〜9, 11, 22, 33）で書き換えられます。
サイト名・ボタン（「数秘を学ぶ」「セッションに申込む」のリンク先 `href="#"`）・フッターは仮の内容です。

## 画像で保存
鑑定後に「画像を作る」を押すと、イメージキャラクター（森の妖精）を真ん中に、
過去数・現在数・未来数（意味のひとことつき）と P・LP・S・M・D の数とキーワードを1枚にまとめた画像を作ります。
「画像を保存」でダウンロード、スマホでは画像の長押しでも保存できます。

## 公開のしかた（note の記事から使ってもらう）
note の記事の中にはこのページを埋め込めないため、ページを別の場所に公開して、記事からリンクします。

1. GitHub のこのリポジトリで **Settings → Pages** を開き、Branch に公開したいブランチと `/ (root)` を選んで保存
   （リポジトリが非公開の場合は GitHub の有料プランが必要です。無料で使うなら Cloudflare Pages や Netlify に `index.html` をアップロード）
2. 表示された URL（例：`https://ユーザー名.github.io/amil_suhi/`）を note の記事に貼る
3. 記事ごとに、URL の最後に `?from=記事の名前` を付ける（例：`…/amil_suhi/?from=note1`）。どの記事から来た人かを計測できます

## 設定（`index.html` の先頭の `CONFIG`）
| 項目 | 内容 |
|---|---|
| `bookingUrl` | セッションの予約ページの URL。空のあいだは予約ボタンを押しても移動しません |
| `shopName` | ヘッダー・フッターに出すお店の名前 |
| `imageFooter` | 保存用の画像の一番下に入れる文字（例：`note @アカウント名 で無料鑑定`）。空ならお店の名前 |
| `gaId` | Google アナリティクス（GA4）の測定 ID（`G-` で始まる）。空なら何も送信しません |
| `abTest` | A/B テストをするか（`false` なら全員に A を表示） |
| `sessionPoints` | 「セッションでわかること」の箇条書き（仮の文章です） |

予約ボタンのリンクには自動で `utm_source=numerology&utm_medium=場所&utm_campaign=ab_A（またはB）&utm_content=来た記事` が付きます。

## A/B テスト
- ページを開いた人をランダムに A と B に分けます（同じ人には同じ方を表示し続けます）
  - A：「より詳しい鑑定はセッションで」
  - B：「あなたの『現在数 3 × 未来数 11』を、くわしく読み解きます」（その人の数字入り）
  - 確認用：URL に `?ab=A` または `?ab=B` を付けると、その方を表示します
- 計測するイベント（名前・生年月日は送りません）：`kantei`（鑑定した）・`make_image`（画像を作った）・`cta_click`（予約ボタンを押した。`position` は result／image／bottom）。どれにも `variant`（A/B）と `from_article`（来た記事）が付きます

### GA4 の準備
1. https://analytics.google.com/ で「プロパティ」を作り、「ウェブ」のデータストリームに公開先の URL を登録
2. 表示される測定 ID（`G-XXXXXXXXXX`）を `CONFIG.gaId` に入れる
3. **管理 → カスタム定義** で、イベントスコープのカスタムディメンション `variant`・`from_article`・`position` を作る（作った後のデータから集計されます）

### 結果の見方
- GA4 の **探索 → 自由形式** で、行に `variant`、値に「イベント数」、フィルタでイベント名 `kantei` と `cta_click` を並べる
- **予約ボタンを押した割合 ＝ cta_click ÷ kantei** を A と B で比べる
- 目安：A・B それぞれ `kantei` が数百回になるまで（2〜4週間）続けてから判断。1回に変えるのは1か所だけにする
